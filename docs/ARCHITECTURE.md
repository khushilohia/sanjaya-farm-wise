# Architecture

_Last updated: 2026-07-19_

## One app, two artifacts

Sanjaya is a TanStack Start application. Frontend and backend live in separate source folders but are compiled by **one Vite build** into two deployable artifacts:

- **Frontend** — static JS/CSS/assets, served from CDN (Vercel) or by the Node server (Docker).
- **Backend** — Nitro server handling SSR and all `createServerFn` RPC endpoints.

The framework generates typed RPC between them, which is why they share a repo and a build — splitting them into two separately-deployed apps would mean replacing the RPC layer with a hand-rolled REST API for no gain at this stage.

## Folder layout

```
src/
  backend/            ← everything that runs on the server only
    api/serverFns.ts    AI chat, STT/TTS, disease detection, soil, market prices
    api/authFns.ts      register/login/logout/getMe + farm data sync
    db.ts               libsql client + schema migration (users, farm_data)
    session.ts          scrypt password hashing + HMAC-signed session cookies
  frontend/           ← everything that runs in the browser
    features/           one folder per feature (weather, soil-health, schemes…)
    pages/              routed page components (dashboard, auth, landing…)
    components/         shared UI (shadcn/ui + layout)
    store/              Zustand stores (auth cache, farm data, server sync)
    hooks/, assets/
  routes/             ← thin TanStack Router glue: URL → frontend page
  lib/                ← shared utilities (i18n, error reporting, cn())
  server.ts, start.ts, router.tsx   framework entries
```

## Backend

- **Server functions** (`src/backend/api/`) are the API. Each is an HTTP POST/GET endpoint generated by TanStack Start with Zod input validation.
- **Database** (`src/backend/db.ts`): libsql. Local dev = `file:./data/sanjaya.db` (zero setup). Production = Turso via `DATABASE_URL` + `DATABASE_AUTH_TOKEN`. Schema is created idempotently on first use — two tables: `users`, `farm_data` (one JSON blob per user).
- **Auth** (`src/backend/session.ts`): passwords hashed server-side with scrypt (per-user salt); sessions are HMAC-SHA256-signed tokens in an httpOnly `sanjaya_session` cookie (30 days). Nothing client-forgeable.

## Frontend

- **Auth state**: `authStore` caches the logged-in user for instant UI; the cookie is the real credential, re-validated on app start via `getMe`.
- **Farm data**: `farmStore` persists to localStorage (offline cache); `farmSync` pushes changes to the server (debounced 2 s) and hydrates from the server on login. Server wins on login; local wins when the account has no server data yet.
- **External data**: weather + rainfall history come from Open-Meteo directly from the browser (no key needed); soil (ISRIC), market prices (Agmarknet), and all AI calls go through server functions because they need API keys.

## Data sources — real vs. sample

| Feature | Source |
|---|---|
| AI chat, disease detection, soil interpretation | OpenRouter → Gemini 2.5 Flash |
| Voice (STT/TTS) | Sarvam AI, with browser Web Speech fallbacks |
| Weather + rainfall history + alerts | Open-Meteo (live, derived in `features/alerts/deriveAlerts.ts`) |
| Soil metrics + health score | ISRIC SoilGrids (live, by GPS) |
| Market prices | Agmarknet via data.gov.in; AI estimate fallback (labelled) |
| Scheme eligibility | Rules in `features/schemes/eligibility.ts` (published scheme criteria) |
| Buyer marketplace, community, admin | Sample/static — labelled as preview in the UI |
